# Nexo 固定皮肤完整主题设计

## 目标

将 12 套 Nexo 固定皮肤从“只替换背景图”升级为完整、精致且可收藏的 Codex 主题。主题必须覆盖侧边栏、新任务页、任务页、输入框、项目选中态和顶部原生区域，同时保留 Codex 的原生布局、交互、可读性和可恢复能力。

## 设计方向

采用“主题签名”方案：12 套皮肤共享一套稳定的原生沉浸结构，每套皮肤通过独立的主题档案控制强调色、辅助色、面板染色、边框亮度、光晕强度和主题签名。效果精致但克制，不添加会遮挡内容的装饰组件。

## 界面规则

### 连续背景

- 新任务页和任务页都显示同一张连续壁纸，不能在首页退化为纯黑背景。
- 12 张固定皮肤源图提升至至少 3840×2400；不得仅放大旧图产生模糊边缘，必须保留原构图并恢复人物、建筑和纹理细节。
- 背景覆盖主内容区，并根据图片焦点保持主体构图。
- 任务页使用更安静的遮罩，首页允许更完整地展示原图。
- 首页背景必须肉眼清晰可辨，禁止使用会将整张图压成近似纯黑或灰雾的全局遮罩。

### 侧边栏

- 使用与当前皮肤主色相匹配的半透明染色面板。
- 增加细边框、内高光和低强度环境阴影，形成与主内容区的空间分层。
- 项目选中态使用主题强调色，而不是所有皮肤共用紫色。
- 图标、文字和滚动区域必须保持原生结构及清晰对比度。

### 新任务页与输入框

- 首页标题保留原生内容，增加低强度主题分隔光线，不修改文字和布局。
- 输入框使用深色主题面板、细描边、内高光和柔和投影。
- 聚焦、悬停和发送按钮使用当前主题强调色。
- 主题签名仅作为小型非交互细节，不能覆盖输入或按钮。

### 任务页

- 保持任务阅读区域安静，背景仍可辨认但不与正文争夺注意力。
- 正文、代码块、弹窗和菜单保持可读，不进行高饱和大面积染色。

## 主题档案

每个固定皮肤包含以下稳定字段：

- `appearance`: 固定为 `dark`。
- `taskMode`: 固定为 `full`。
- `accentRGB`: 主强调色。
- `secondaryRGB`: 辅助色。
- `panelRGB`: 侧边栏和输入框的染色色基。
- `glowStrength`: 光效强度，限制在低到中等级。
- `signature`: 短主题签名。
- `focusX` / `focusY`: 原图视觉焦点。

macOS 和 Windows 必须由同一份主题档案语义生成主题，避免两端效果漂移。用户自行导入的图片继续使用通用自适应配置，不强制套用固定皮肤的签名风格。

## 安全和兼容边界

- 不修改官方 Codex 应用、`app.asar` 或签名。
- 所有装饰层使用 `pointer-events: none`。
- 不改变任何原生按钮、菜单、输入框或导航的点击区域。
- 支持 Intel Mac、Apple 芯片 Mac 和 Windows。
- 尊重减少动态效果设置；第一版仅使用静态光效和原生状态过渡。
- 应用主题时优先热更新；未经用户明确许可不得重启正在运行的 Codex。

## 验收标准

1. 12 套皮肤逐一生成并携带不同的主题色档案。
2. 12 张线上原图均达到至少 3840×2400，格式、完整性和文件体积通过自动检查。
3. 新任务页、普通任务页均能看到连续背景，首页主体和环境细节清晰可辨。
4. 侧边栏、项目选中态和输入框与当前主题色协调。
5. 主题之间切换后颜色和签名同步更新，不残留上一主题样式。
6. 原生侧边栏、正文区和输入框可见，页面无横向或纵向溢出。
7. macOS 通用助手构建成功；Windows 主题档案和应用链路通过测试。
8. 恢复官方外观后，所有主题样式和装饰均被移除。

## 不在本次范围

- 不新增宠物、粒子动画、音效或皮肤商城机制。
- 不修改平台充值和权限发放逻辑。
- 不为用户自定义图片自动生成独立品牌签名。
